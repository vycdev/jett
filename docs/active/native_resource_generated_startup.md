# Generated Resource object startup prerequisite

This restored bounded implementation connects the selected Resource ownership
contract to the normal launcher. It changes no public Source policy and supplies
no production I/O provider. Authoring was based on published GNU f4/v25. The
current Actor/Resource/Owner/reuse/Callback compiler passes local MSVC focused
controls, the existing private Resource gates and the complete bounded 80-row
startup matrix. Full-workspace/native conformance, exact-revision CI, GNU,
installed distribution and public-provider acceptance remain pending. Earlier
isolated results below are historical handoff claims; they do not validate the
current restored compiler or its archives.

The normal `jett_aot_v1_entry(context) -> u32` ABI is preserved. A Resource object
calls its own immutable `jett_aot_resource_v1_manifest` accessor into a distinct
32-byte stack record, then calls `jett_rt_v1_resource_program_begin`. Ordinary
objects do not reference either operation. The shared launcher never imports an
optional manifest symbol.

Begin validates every known input/output/context region before any effect. Under
the same authenticated stationary-context lease, the existing installation
issuer decodes the checked layout, validates the exact entry and retains an owned
byte-for-byte copy before provider/grant publication. Generated ownership fixes
purpose to Runtime. Different wire bytes/entries and active reentry refuse; exact
reentry after completed retirement uses the existing new-attempt constructor.
No error channel is reset, overwritten or transferred to legacy session state.

The normal provider remains Disabled. Its entry installation receives no paired
Network grant, and actual Network/resource use refuses. This is startup plumbing,
not a real creation/use/drop or production I/O acceptance receipt. The exact
Network-only/Nothing entry boundary is retained for this prerequisite; supporting
mixed ordinary capabilities such as Stdout is still a required subsequent step.

After successful begin, every generated body/refusal return goes through normal
completion once. The core retains the original body status, first ordinary and
Resource diagnostics, first cleanup status and independent selected kind. A
separate private terminal-status field covers recorded first errors even when the
original body status is zero, without changing the existing completion record
ABI. Cleanup retains priority. Report-allocation failure retains a tombstone and
blocks new attempts; failed retirement remains observable and is never retried as
though it had succeeded.

The normal launcher reads the retained Resource outcome and copies its selected
diagnostic while the context is alive. Ordinary contexts keep the previous value
failure path. After a recoverable entry panic, the launcher completes only a
Generated-owned Running attempt, before its existing single context destruction.
The returned selected kind distinguishes host panic from cleanup failure even
when both statuses are 255. An existing Completing attempt is refused, never
restarted. Ordinary contexts and externally managed private attempts are no-ops.

Only `cfg(all(test, jett_resource_native_test_archive))` admits an exact already
Running Runtime attempt owned by the scripted private installer. Begin returns a
zero borrowed-attempt sentinel solely for this generated-wrapper compatibility
branch; the private runner remains responsible for completion and retained
telemetry. Production cannot adopt externally owned custody. Explicit comptime,
verify and property attempts cannot pass this Runtime-only handoff.
